# 多人测试清单（2 客户端）

> 本文件只讲"怎么验"，不讲设计。跑之前先 `/reload`，并且**两名玩家都要是同一个存档里的正版/离线账号**，
> 用「打开对局域网开放」或直接开专用服即可（单人存档点对局域网开放后，第二个客户端可从"多人游戏 → 局域网世界"进入）。

## 0. 前置：两个人怎么进来的

| 情况 | 会发生什么 |
|---|---|
| 两人都在 `/reload` 之前就在线 | `tspire:load` → `load/join` 把两人都拉进 `tspire_party` 队伍 |
| 有人在 `/reload` 之后才登录 | `tick/second` 每秒会把**没入队的非旁观玩家**自动拉进队伍（v0.6.20 新增） |
| 开了一局之后才想加人 | `/function tspire:run/join_mid`（v0.6.20 新增）：传送队伍身边 + 补一套当前层装备 + 补开局金币 |

随时可以用 **`/function tspire:test/mp_check`** 打印全队状态（每人的 phase / 层 / 金币 / 武器数 / 阵亡 / 是否已领奖励 / 是否在服务节点），
以及"哪些人还没入队"。排查多人问题时**先跑这个**。

---

## 1. 开局构筑：两个人各自一份选项

1. A 执行 `/function tspire:run/start`。
2. **两边都应看到**护甲菜单（4 个部位 × 3 个选项）。
   - ❌ 只有一个人收到菜单 = 失败，记下来。
3. **两个人的选项必须是各自随机抽的、互不相干**（v0.6.23）。
   - 验证：`/function tspire:test/mp_check` → 每人的 `draft=` 值可能相同也可能不同；
     重点看两人的**选项内容**是否不同（同一个 `draft` 号才会一样，重开一局多半不同）。
   - 同一个部位里出现两条一样的套装说明是**允许**的（设计如此），不用管。
   - ❌ 两个人看到的整套列表完全一样 = 失败（说明还在共用一份方案）。
4. 点某个部位 → 菜单重新渲染一次（已选的变灰）。点**已经选过**的选项只提示
   「这个部位已经选过了。」，**不再整屏重发菜单**。
5. A 先把 4 件护甲 + 2 把武器选完，**先不要**让 B 选完。
   - 预期：A 收到「你的武器选好了，等其他队友选完就开局。」，**全队不会开跑**。
6. B 也选完 → 这时才开局：两边同时收到"第 1 层"标题、bossbar 出现。
7. **关键验证**：两人各自拿到的是**自己那份菜单上写的装备**（不是别人那份）。
   - 实现方式：取货前会先把箱子按"你自己那份方案"重摆一次。
8. 检查：`/function tspire:test/mp_check` → 两人 `武器数` 都应该是 2，`phase` 都应该是 5。

## 2. 战斗：封门不会把人关在外面，也不会把人传走

1. 两人一起往北走。**A 先进房间**触发战斗，B 故意慢一步留在走廊里。
2. 预期：战斗开始的瞬间，B 被自动拉进**当前这个房间**。
   - ❌ B 被 barrier 挡在门外 = 失败。
   - ❌ B 被传送到**上一层**的工匠/商人房间 = 失败
     （v0.6.22 修的 `tspire_node_current` 不唯一问题）。
3. 打的过程中确认：怪会打两个人、Boss 的 AOE（如淬火者的烈焰环）对两个人同时生效。
4. 打完 → 两人都该看到奖励。
   - **战斗奖励与宝箱奖励必须是每人各自骰的**（v0.6.23）：两个玩家拿到的随机奖励
     应该**不一样**。以前 `loot give @a[...]` 只骰一次、结果发给所有人，所以人人相同。

## 3. 三选一奖励：看得见、且不同人拿不同东西

1. 战斗结束后，聊天栏出现 `[奖励] 三选一（按你手上的〈工具名〉抽的）`，
   后面三行**写明每件候选的部件名与材料**（例如「[候选 2] 工具手柄 · 铁」），
   鼠标悬停还有一行详细说明。**每名玩家看到的是自己那一份**（按自己手持的工具抽的）。
   - ❌ 只写「候选 1/2/3」看不到是什么 = 失败（v0.6.22 之前就是这样）。
2. **A 手持剑，B 手持镐**（或任何不同的匠魂工具）。
   - 预期：两人的候选**不一样**（各自对应自己的工具）。
3. A 点「候选 1」，B 也点「候选 1」。
   - 预期：各拿各的，且拿到的就是菜单上写的那件。
4. 同一个人再点一次任何按钮 → 应提示「你已经领过这一份奖励了。」
5. 多人的语义：**每人各领一份**（箱子只是视觉标志），玩家不会互相抢。
6. 用 `/function tspire:test/reward_demo` 可以跳过打怪直接出这个三选一；
   想看第 2/3 层的候选池就把 `#FLOOR` 改一下再执行。

## 4. 商人 / 工匠节点

1. 两人一起进商人房间，**两边都应弹出菜单**（第二次走回来也应该还能用）。
   - ❌ 走进去完全没反应 = 失败。v0.6.21 就是这样：`map/enter_merchant` 里
     一句 `execute unless score @s tspire_shop_f = #FLOOR` 少了第二个计分板名，
     Brigadier 解析失败导致**整个函数加载不了**（见 `latest.log` 的
     `Failed to load function tspire:map/enter_merchant`）。v0.6.22 已修。
2. **每人的商店不一样**：货架编号挂在玩家身上（`@s tspire_shop_l`，1~8），
   两人各自抽、互不影响。用 `/function tspire:test/mp_check` 可以看到各自的"货架：层/编号"。
   - 验证：A 买第 1 格，B 点第 1 格 —— B 看到的商品名/价格应该和 A 不一样（多半不一样），
     而且 **B 也能买**（同一格）。
3. **每人每格限购一次**：同一格再点会提示「这一格你已经买过了（每人每格限购一次）。」，
   金币不会被重复扣。
4. 换层之后会自动重抽一份；同一层反复进出不会刷新商品。
5. 工匠节点：回血对两人都生效；部件制造台的模具只在槽空时放一次。

## 5. 阵亡 / 旁观 / 复活 / 失败

1. 让 A 被打死 → A 变旁观、聊天栏播报「A 倒下了」；
   **A 应该立刻出现在 B 身边**（不是回主世界、也不是丢在层起点）。
   - ❌ 观战画面一黑、人到了主世界 = 失败（v0.6.24 之前就是这样）。
   - ❌ 人在塔里但离 B 很远、什么都看不到 = 失败。
2. 让 B 走一段路 → A（旁观）身边 16 格内没有活队友时会被自动拉过去跟队，
   **不会飘出地图**。
3. B 把怪清完 → A 应**在队友身边**复活（冒险模式、只保留 25% 生命）。
4. 单独验证"出图兜底"：本局进行中让 A 执行
   `/execute in minecraft:overworld run tp @s 0 100 0`，
   下一 tick 应被自动拉回队友身边（只在 `#RUN_STARTED=1` 且 `phase=5` 时生效）。
5. 再让两人同一次战斗中先后死掉 → 全队阵亡 → 结算界面（失败版）+ `[ 再来一局 ]`。

## 6. 结算界面

1. 通关或全灭后，**每个人看到的是自己的成绩**（层数 / 通过节点 / 用时 / 金币 / 本局阵亡）。
2. 想不打通关直接看排版：`/function tspire:test/summary`。

## 7. `/reload` 与中途加入（本次修的一处大 bug）

1. 打到第 2 层，塔里执行 `/reload`。
   - 预期：本局**继续**，bossbar 5 秒内自动回来，全队 `phase` 不变、**金币不变**。
   - 旧版：`tspire:load → load/join` 会把所有人的 `phase` 和**金币清零**，等于悄悄废掉这一局。
   - 验证：reload 前后跑 `/function tspire:test/mp_check`，对比金币。
2. reload 之后 A 再执行 `/function tspire:run/start` → 应被拒绝，并给出「加入这一局 / 强制重开」两个按钮，
   **不能**直接把正在进行的局重置掉。
3. 关掉第二个客户端再重新进来（不清存档），执行 `/function tspire:run/join_mid`
   → 应被传送到 A 身边并拿到一套当前层装备。

## 8. v0.6.26 新机制（单人也能验，多人重点看"每人各自结算"）

> 这一节是 v0.6.26 的八项调整。**每条都能单人验**；标了"多人"的那几点要 2 客户端。

1. **水晶概率 + 金苹果（奖励池）**
   - 打几场战斗，看随机奖励里**强化水晶明显变多变**、并且能出 **金苹果**（`minecraft:golden_apple`）。
   - 水晶**不应该**再开出采掘类：**烧炼 / 急迫 / 爆裂 / 光照提速 / 水力驱动 / 丝触 / 置换 / 自动烧炼** ——
     抽到这些就是池子没过滤干净。
   - **幸运（Luck）水晶仍然应该出**（它同时给抢夺）。
   - 离线对照：`loot_tables/rewards/crystal.json` 应是 **89** 条；
     `battle_random_f1.json` 权重应为 **22 / 16 / 38 / 8 / 15 / 0.5 / 0.5**，`rolls: 2`。
2. **Boss 技能提示**：`/function tspire:test/boss_demo_f1` 进 Boss 房（或直接用 `/function tspire:boss/active` 刷）。
   - 每个技能都应出现 **(a) actionbar 加粗大字**（带技能名，各 Boss 颜色不同）+ **(b) 一声专属音效**。
   - 四个危险技能还应有**聊天栏一行操作提示**：
     **淬火者·烈焰环**「先退开」/ **沼泽猎手·毒标枪**「别站桩」/ **铭刻者·镜像分身**「分辩分身」/ **熔核暴君·熔火地脉**「换位」。
   - actionbar **不应刷屏**（每次覆盖）；聊天栏提示**每个冷却周期只出现一次**。
   - 音效要能听见（用的是 `master` 声道，不是 `player`）。
3. **怪物刷在正前方**：进一个战斗房间（玩家从南门进、往北走）。
   - 编队应出现在**玩家前方（北侧）**迎面列阵，**不是**一进门就被人从**背后**打。
   - 同组内仍然每 3 人一行、行距 2 格。
4. **三选一算上身上穿的护甲**（多人各验一遍）
   - **把主手空出来**（或拿一件非匠魂物品），但**身上穿着**镶板 / 旅行者 / 黏液护甲 → 打完一场，
     三选一的候选应该仍然是**自己护甲用得上的部件**（不再是"通用材料池"兜底），菜单抬头会写按哪件装备抽的。
   - 再试：**手上有可改造匠魂工具**时 → 仍然按**手上那把**抽（优先级：主手 > 胸甲 > 护腿 > 靴子 > 头盔）。
   - 全部脱光、手上也没东西 → 应回退到**通用材料池**（菜单抬头是通用那份）。
5. **工匠节点回血 45% + 付费 25%**
   - 把血扣到较低（例如 `4`）再进工匠节点 → 聊天栏「已恢复 45% 生命」，血应该 **+9**。
   - **容差**：把血扣到 **9~11** 再进 → 只会 **+8**（差 1 点是刻意的，原版效果粒度所限）；血很高时只顶到满血。
   - 菜单里点 `[回血]`，**花 25 金币再回 5 点**；钱不够应提示「金币不足（需要 25 金币）。」且**不回血**。
   - 血量在 11 以下时付费档应**正好 +5**；**身上有吸收（absorption）时会偏多**（那 3 点修正伤害被吸收挡掉了），这是已知副作用。
   - **多人**：两个人一起进节点，**各自**都要回血（`as @a[team=tspire_party] run function tspire:artisan/heal_free` 逐人跑；`heal_snapshot` 已在 v0.6.27 删除，血量快照折进 `heal_free` 开头）。
6. **弓有自容箭袋、且真的有箭**
   - 开局选到长弓 / 弩（或去商人节点买一把远程武器）→ 拿到手应显示 **「自容箭袋」** 强化。
   - `run/give_kit` 应给 **32 支箭**：按 `E` 看背包里有 `minecraft:arrow` ×32。
   - **实射**：拉弓 / 装填弩能正常打出箭（因为 `bulk_quiver` 是 `check_standard_arrows: true`，
     **先吃背包里的普通箭** —— 如果没发箭，弓就是废铁）。
   - 箭用完**不会自动补**，需要在商人 / 工匠节点补（预期行为）。
7. **宝箱节点回血**
   - 走进宝箱节点 → 聊天栏「[宝箱节点] 获得一件匠魂装备。（并恢复 20% 生命）」，
     血应该 **+4**（`instant_health` amplifier 0 = 正好 4 点）。
   - **多人**：两人一起进，**各自**都要 +4（逐人 `map/chest_heal`）。

## 9. v0.6.27 新机制与三个 bug 修复（每条都能单人验；商人那几条建议 2 客户端）

> 这一节对应三个**根因修复**（商人买不了 / 低血进门不回血 / 封口石没生效）与六项新机制。
> 三个 bug 都先看 `latest.log` 再动手 —— **注意日志是 GBK / ANSI 编码，用 UTF-8 读全是乱码**。

1. **商人不许"跨局 / 跨节点"带限购状态**（修"商人买不了东西"）
   - 开一局，去商人节点**买掉第 1 格**（应成功、扣钱、拿到货）。
   - **重开一局**（`/function tspire:run/start` 或先在结算界面点 `[ 再来一局 ]`），
     走到商人节点点第 1 格 → **必须能买**。
     ❌ 提示「这一格你已经买过了（每人每格限购一次）。」= 失败（旧 bug 就是这样）。
   - 同一局里**换一个商人节点**（换行 / 换层）→ 点是全新货架、第 1 格能买；
     **回到同一个商人节点** → 货架、价格、`已买过` 状态**都不变**。
   - 离线对照：点购买后日志里那次调用若是**只有 9 条命令**，说明走的是**拒绝分支**（真买成功是 78 条）。
   - **多人**：A 买第 1 格后，B 在自己的商人节点**照样能买第 1 格**（每人一份货架，见 §4）。
2. **只剩一滴血进工匠 / 宝箱节点不会死、而且真的会回血**
   - 用 `/damage @s 19` 之类把血压到 **1 点**（`/scoreboard players get @s tspire_hp` 确认为 1），
     再走进**工匠节点** → 聊天栏「已恢复 45% 生命」，血应该**立刻涨上去**（不是 0 回复）。
     ❌ 血一点没变、随后被一个中毒 / 凋零 tick 带走 = 失败（旧 bug：`#HP0` 被队友血量覆盖）。
   - **多人**（重点）：两人**都残血**、或一人满血一人 1 点，一起进工匠节点 →
     **两个人各自都要回血**（`heal_free` 现在开头自己取 `@s` 的血，一圈 `as @a` 搞定）。
   - 宝箱节点同样验一次：1 点血走进去应该 +4（§8 第 7 条）。
3. **服务节点也会锁掉本行**（修"封口石没生效"）
   - 在第 N 行走进**宝箱 / 商人 / 工匠**节点，办完事从出口退回走廊 →
     **本行其它没选的房间应该是封死的**（`polished_blackstone_bricks` 封条，开不了门、进不去）。
     ❌ 还能钻进同一行别的房间 = 失败。
   - 再验一次普通战斗节点：行为应该与修前一致（一样封死）。
   - 服务节点**本身仍可回头再用**（可复用节点，`refresh_doors` 会开 `current`），只是**本行别的房间**被封。
4. **战斗房编队再往北 2 格**
   - 进战斗房（南门进、往北走）：编队应出现在**正前方更远处**，从门口能看到他们在列阵，
     **不会一进门就贴脸**。同组仍是每 3 人一行、行距 2 格。
5. **工匠「修复」三项调整**
   - 先把**背包里的备用工具**打坏（比如主手放一把、背包第 1 格再放一把都磨到残耐久）。
   - 点菜单 `[修复]` → **两把都修满**（范围是整个物品栏 `container.0..35`，不再只有 6 个装备槽）。
   - 同时应收到 **32 支箭**（背包里 `minecraft:arrow` +32）。
   - **价格递增**：菜单上第一次显示 **15**，修完再看 `@s tspire_repair_cost` 应该是 **20**、
     第二次修完 **25**（每次 +`#CFG_REPAIR_COST_STEP`，默认 5），金币按菜单显示的数扣。
   - 钱不够时应提示「金币不足，本次修复需要 N 金币。」且**不修、不扣钱**。
6. **工匠「共鸣」**
   - 菜单点 `[共鸣]` → 扣 **30 金币**，拿到 **1 枚强化水晶**（`tconstruct:modifier_crystal`）。
   - **同一局再点** → 提示「共鸣每局只能用一次。」，**不再扣钱**。
   - 金币 < 30 时点 → 提示「金币不足（共鸣需要 30 金币）。」，不扣钱、不发奖。
   - 开新一局后可以再用一次（`tspire_resonate_used` 在 `run/reset_player` 里清零）。
   - 抽到的水晶**不应**是采掘类（见 §8 第 1 条）。
7. **Boss 技能 2 秒前摇**
   - `/function tspire:test/boss_demo_f1`（f2/f3）或直接打一场 Boss。
   - 每个技能生效**之前**都应先看到：**(a)** 一行黄色加粗 `⚠ 【技能名】准备中 —— …`（actionbar）；
     **(b)** Boss **明显变慢**（`slowness` 每 tick 刷新，前摇 2 秒内一直是慢的）；
     **(c)** 有范围判定的技能还会在**东西南北四个方向**各亮一个 `end_rod` 粒子点（半径 = 技能实际范围）。
   - 2 秒之后才轮到原来的效果那一拍（actionbar 大字点名 + 专属音效 + 危险技能的聊天栏提示）。
   - **有环的技能**：淬火者·烈焰环（8 格）、沼泽猎手·毒标枪（6 格）、铭刻者·镜像分身（20 格）、
     熔核暴君·熔火地脉（6 格）；**自身增益 / 召唤类**（锈刃督军、钴蓝决斗者、裂颅者、织影巫师、重铸之王）**没有环**，只有预告 + 减速。

### 11.2 工匠「融合」

1. **前置**：进工匠节点，**主手 + 副手各拿一枚材料部件**（例如两枚工具手柄），并确保金币 **≥ 30**。
2. 菜单里点 **`[融合]`**。
   - 预期：**扣 30 金币**；**主手与副手两枚部件都消失**；背包里多出 **一枚与主手同类型**的部件，
     材料来自**更高一层的材料池**（第 1 层点 → 第 2 层池；第 2 / 3 层点 → 第 3 层池）；
     并有音效 + 粒子 + 「融合成功！两枚部件已消耗。剩余金币：X」。
   - ❌ 两枚部件还在、或发的部件类型和主手不一样 = 失败。
3. **同一工匠节点再点一次** → 必须被拒：「这个工匠节点已经融合过了。」，且**不扣钱、不消耗部件**。
   - 换一个工匠节点（换行 / 换层）→ 可以**再融合一次**（"每个工匠节点限一次"，不是整局限一次）。
4. **三道门禁各验一次**（都不扣钱、不消耗）：
   - 只拿主手、副手空着 → 「融合失败：副手也需要持有一枚部件。」；
   - 主手拿的不是部件（例如拿工具）→ 「融合失败：主手需要持有一枚部件。」；
   - 金币 < 30 → 「融合失败：金币不足（需要 30 金币）。」。
5. **多人**：A 在某个工匠节点融合过之后，B 在**同一个**节点**仍然可以**融合一次
   （`tspire_fuse_used` 是**逐人**计分板）。
